\section{Discussion and Conclusion}
\label{sec:conclusion}

\subsection{Flash Storage and Hardware Roots of Trust}
On modern solid-state drives (SSDs) and mobile flash storage (eMMC/UFS), internal Flash Translation Layers (FTL) perform out-of-place writes for wear-leveling, leaving stale physical pages readable until garbage collection~\cite{wei2011reliably}. VANISH addresses this physical constraint via Tier 2 Crypto-Shredding~\cite{diesburg2010survey, geambasu2011keymon}. By encrypting payloads with AES-256-GCM and maintaining Content Encryption Keys exclusively within hardware keystores (ARM TrustZone or TPM 2.0), key deletion at $t \ge t_{\text{exp}}$ renders remaining flash ciphertext mathematically indecipherable.

To defend against privileged local adversaries manipulating system clocks, deployments anchor time checkpoints to non-volatile hardware monotonic counters—such as the Replay Protected Memory Block (RPMB) in mobile UFS storage or TPM 2.0 NV counters~\cite{tpm20specification}—coupled with authenticated network time (NTS~\cite{rfc8915nts} and Roughtime~\cite{roughtime2018}).

\subsection{Limitations and Future Work}
While VANISH prevents offline accumulation and storage remanence, it cannot prevent an authorized user from capturing plaintext or photographing a display while the file is currently valid. Future extensions include: (i) hardware-enforced transient framebuffers using confidential computing enclaves (e.g., ARM Realm Management Extension / RISC-V Keystone), (ii) post-quantum migration to NIST FIPS 203/204 algorithms (ML-KEM and ML-DSA), and (iii) multi-party threshold expiration policies where deletion requires quorum consensus.

\subsection{Conclusion}
In this paper, we presented \textbf{VANISH}, an open, cross-platform protocol and operating system architecture for cryptographically verifiable, self-expiring digital files. By coupling canonical CBOR metadata, Ed25519 digital signatures, and authenticated AES-256-GCM encryption with native operating system storage monitors, VANISH bridges the gap between ephemeral messaging sandboxes and permanent filesystem storage.

Our reference implementation—comprising a desktop Linux daemon (\texttt{vanishd}) and an Android AOSP framework service (\texttt{VanishManagerService})—demonstrates that native lifecycle governance incurs strictly bounded framing ($140$\,bytes fixed, $320$--$429$\,bytes total with manifest), verifies a $1$\,MB container in $\approx 1.38$\,ms, and runs with negligible idle battery drain ($<0.05\%$ over 24 hours). By providing formal reductions across realistic enterprise and consumer threat models, VANISH establishes an open foundation for automated digital privacy.
