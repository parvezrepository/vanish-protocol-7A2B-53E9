\section{Discussion and Conclusion}
\label{sec:conclusion}

\subsection{Flash Storage and Hardware Roots of Trust}
Modern solid-state drives and mobile flash memory (eMMC/UFS) utilize internal Flash Translation Layers (FTL) that perform out-of-place writes for wear-leveling, leaving stale physical pages readable until garbage collection~\cite{wei2011reliably}. VANISH addresses this physical constraint via Tier 2 Crypto-Shredding~\cite{diesburg2010survey, reardon2013sok}: by encrypting payloads with AES-256-GCM and maintaining Content Encryption Keys exclusively within hardware keystores (ARM TrustZone TEE or TPM 2.0 / Secure Element), key deletion at $t \ge t_{\text{exp}}$ renders remaining flash ciphertext computationally indecipherable. To counter clock rollback in offline environments, time checkpoints are anchored to non-volatile monotonic hardware counters (eMMC/UFS RPMB or TPM 2.0 NV counters~\cite{tpm20specification}) coupled with authenticated network time (NTS~\cite{rfc8915nts}, Roughtime~\cite{roughtime2018}).

\subsection{Limitations and Future Work}
While VANISH prevents offline accumulation and storage remanence, it cannot prevent an authorized user from capturing plaintext or photographing an active display while the file is currently valid. Future extensions include: (i) hardware-enforced transient framebuffers using confidential computing enclaves (e.g., ARM Realm Management Extension / RISC-V Keystone), (ii) post-quantum migration to NIST FIPS 203/204 algorithms (ML-KEM and ML-DSA), and (iii) multi-party threshold expiration policies where deletion requires quorum consensus.

\subsection{Conclusion}
We presented \textbf{VANISH}, an open protocol and OS architecture for cryptographically authenticated, self-expiring digital files. By coupling canonical CBOR metadata, Ed25519 digital signatures, and authenticated AES-256-GCM encryption with native operating system storage monitors, VANISH bridges the gap between ephemeral messaging sandboxes and permanent filesystem storage. Our reference implementation demonstrates strictly bounded framing ($140$\,bytes fixed, $320$--$429$\,bytes total), fast verification ($1.42$\,ms for $1$\,MB), and negligible idle battery drain ($<0.05\%$ over 24 hours).
